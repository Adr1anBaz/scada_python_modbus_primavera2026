1. Panorama General

El sistema integra un robot UR3 (Universal Robots) con los PLCs Horner XL4 del sistema de bandas. El robot manipula cajas usando una garra OnRobot controlada por un dispositivo llamado Eye Box.

El problema fundamental es que el UR3 y los PLCs estan en redes diferentes:

Equipo Red Razon
Robot UR3 + Eye Box 192.168.1.0/24 El Eye Box esta configurado de fabrica en esta red
PLCs Horner 192.168.3.0/24 Red del sistema de bandas transportadoras

Para que el PLC Horner se comunique con el UR3 via Modbus TCP, se utiliza una PC Windows con dos interfaces de red que actua como router entre ambas redes.

Robot UR3 con garra OnRobot montada. La garra se controla via el Eye Box.

2. Por que el UR3 esta en la red .1

Restriccion de hardware: El dispositivo OnRobot Eye Box viene preconfigurado en la red 192.168.1.x y requiere que el robot UR3 este en la misma subred para comunicarse con la garra.

El OnRobot Eye Box es el controlador de la garra robotica. Este dispositivo:

  • Tiene una IP fija en el rango 192.168.1.x
  • Se conecta al UR3 por Ethernet para enviar comandos a la garra
  • Requiere que el robot este en la misma subred (192.168.1.0/24)

OnRobot Eye Box con conexiones Ethernet (cable azul) y alimentacion 24V. Este dispositivo obliga al UR3 a permanecer en la red 192.168.1.x.

Como no se puede cambiar la red del Eye Box sin riesgo de perder la comunicacion con la garra, la solucion es mantener al UR3 en la red .1 y usar la PC como puente hacia la red .3 donde estan los PLCs.

En resumen: El Eye Box fuerza al UR3 a quedarse en la red .1. La PC Windows resuelve esto actuando como router entre las dos redes.

4. Conceptos de Red Necesarios

Subred

Un grupo de equipos que comparten un rango de IPs y pueden comunicarse directamente entre si sin necesitar un router. La notacion /24 significa mascara 255.255.255.0 (los primeros 3 octetos identifican la red, el ultimo identifica al equipo).

Gateway (puerta de enlace)

Es la IP del equipo al que un dispositivo envia paquetes cuando el destino esta en otra red. Si el UR3 quiere hablar con un PLC en la red .3, envia el trafico a su gateway (192.168.1.28 = la PC Windows).

Router

Equipo con interfaces en dos o mas redes que reenvía paquetes entre ellas. En este caso, la PC Windows cumple ese rol porque tiene una interfaz en la red .1 y otra en la red .3.

IP Forwarding

Funcion del sistema operativo que permite reenviar paquetes de una interfaz de red a otra. Por defecto Windows NO lo hace (solo procesa paquetes dirigidos a si mismo). Hay que habilitarlo explicitamente.

5. Como Funciona Windows como Router

La PC Windows tiene dos interfaces de red activas simultaneamente:

  • Ethernet: conectada fisicamente al UR3 (192.168.1.28)
  • Wi-Fi: conectada a la red de PLCs (192.168.3.228)

Parte trasera de la PC Windows mostrando las conexiones Ethernet (cable azul hacia el UR3) y de red.

Flujo de un paquete PLC → UR3

  1. El PLC quiere enviar datos a 192.168.1.76 (el UR3)
  2. Como esa IP no esta en su red local .3, envia el trafico a su gateway: 192.168.3.228 (la PC)
  3. Windows recibe el paquete por su interfaz Wi-Fi
  4. Windows ve que la red 192.168.1.0/24 esta conectada directamente por su interfaz Ethernet
  5. Windows reenvia el paquete al UR3 por Ethernet
  6. El UR3 responde enviando a su gateway 192.168.1.28 (la PC)
  7. Windows devuelve la respuesta al PLC por Wi-Fi

6. Configuracion del UR3

En el Teach Pendant del robot:

  1. Ir a Setup → Network
  2. Seleccionar Static Address
  3. Configurar:
    ParametroValor
    IP Address192.168.1.76
    Subnet Mask255.255.255.0
    Default Gateway192.168.1.28
  4. Aplicar y reiniciar la interfaz de red del robot
El gateway es clave: Sin gateway configurado, el UR3 solo puede hablar con equipos en su propia red (.1). El gateway 192.168.1.28 le dice al robot "para alcanzar otras redes, manda los paquetes a la PC Windows".

Controlador del UR3 con las conexiones Ethernet visibles en la parte inferior.

8. Habilitar IP Forwarding en Windows

Por defecto Windows no reenvia paquetes entre interfaces. Hay que habilitarlo manualmente desde PowerShell como Administrador.

Paso 1: Habilitar forwarding en ambas interfaces

Set-NetIPInterface -InterfaceAlias "Ethernet" -Forwarding Enabled
Set-NetIPInterface -InterfaceAlias "Wi-Fi 3" -Forwarding Enabled
Nota: Los nombres de interfaz ("Ethernet", "Wi-Fi 3") pueden variar segun el equipo. Usar Get-NetIPInterface para ver los nombres exactos.

Paso 2: Verificar que forwarding esta activo

Get-NetIPInterface -AddressFamily IPv4 | Format-Table ifIndex,InterfaceAlias,Forwarding,ConnectionState

Debe mostrar Enabled en las interfaces Ethernet y Wi-Fi.

Paso 3: Habilitar el ruteo global IPv4

# Verificar valor actual:
Get-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters" -Name IPEnableRouter

# Si no esta en 1, activarlo:
New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters" -Name IPEnableRouter -PropertyType DWord -Value 1 -Force
Requiere reinicio. Despues de cambiar IPEnableRouter a 1, reiniciar la PC para que tome efecto.

Paso 4: Verificar la tabla de rutas

route print

Deben aparecer rutas directas (On-link) para ambas redes:

192.168.1.0    255.255.255.0    On-link    192.168.1.28
192.168.3.0    255.255.255.0    On-link    192.168.3.228
Ruta incorrecta: Si aparece una ruta de 192.168.1.0 saliendo por 192.168.3.228, esta mal configurada y debe eliminarse con: route delete 192.168.1.0

9. Configuracion del PLC Horner

El PLC que se comunicara con el UR3 debe tener configurado un gateway que apunte a la PC Windows:

ParametroValor
IP del PLC192.168.3.12
Mascara255.255.255.0
Gateway192.168.3.228
Por que este gateway? Desde el punto de vista del PLC, la red 192.168.1.0/24 (donde esta el UR3) no es su red local. Para alcanzarla, necesita enviar el trafico a un router. La PC Windows en 192.168.3.228 es ese router.

Esto se configura en Cscape dentro de la configuracion del puerto Ethernet del PLC.

10. Configurar Modbus Client en Horner (Cscape)

Activar el protocolo

En Cscape, dentro de la configuracion LAN del PLC:

  • Ir a la configuracion del puerto Ethernet
  • En Downloadable Protocol, seleccionar: Modbus Client

Esto hace que el PLC sea el cliente Modbus/TCP que se conecta activamente al UR3 (servidor).

Crear el dispositivo UR3

Definir un nuevo dispositivo con:

CampoValor
NameUR3
Target IP192.168.1.76
Port502
AddressingModicon PLC 5-Digit Addressing

Configurar el Scan List

El scan list define que registros se intercambian ciclicamente entre el PLC y el UR3. Ejemplo minimo:

CampoValorExplicacion
Device Register40002Registro Modbus del UR3 a leer/escribir
Length1Cantidad de registros
Local Register%R00004Registro local del Horner donde se guarda el valor
Update TypePolled Read/WriteLectura y escritura ciclica

Esto significa: el Horner intercambiara ciclicamente el valor de su registro local %R00004 con el registro Modbus remoto 40002 del UR3.

11. Verificacion y Diagnostico

Desde la PC Windows

# Verificar que la PC llega al robot:
ping 192.168.1.76

# Verificar tabla ARP (el robot debe aparecer):
arp -a

# Verificar trafico en puerto Modbus:
netstat -ano | findstr :502

Desde el PLC (Cscape)

  1. Descargar el proyecto al PLC
  2. Poner en modo Run
  3. Observar el valor de %R00004 (o el registro local configurado)
  4. Forzar valores de prueba (4, 0, 8, 5) para verificar que se escriben al UR3

Desde el UR3

  • En el Teach Pendant, revisar la seccion de I/O → Modbus
  • Verificar que los registros esperados estan expuestos
  • Si no hay cambios a pesar de que la red funciona, el problema es de mapeo de registros en el lado UR

12. Referencia de Comandos Windows

Comando Funcion
ipconfig Ver IPs, mascaras y gateways de cada interfaz
ping 192.168.1.76 Verificar conectividad IP con el UR3

13. Errores Comunes y Soluciones

El ping al UR3 no responde desde Windows

  • Verificar que el cable Ethernet esta conectado entre la PC y el controlador del UR3
  • Verificar que la interfaz Ethernet de la PC tiene IP 192.168.1.28
  • Verificar que el UR3 tiene IP 192.168.1.76 con mascara 255.255.255.0
  • Verificar que el firewall de Windows no bloquea ICMP

El PLC no llega al UR3

  • Verificar que el gateway del PLC es 192.168.3.228
  • Verificar que IP Forwarding esta habilitado en ambas interfaces de Windows
  • Verificar que IPEnableRouter = 1 en el registro de Windows
  • Verificar con route print que no hay rutas conflictivas

Hay ping pero Modbus no funciona

  • El UR3 debe tener el servidor Modbus activo (puerto 502 escuchando)
  • Verificar que el mapeo de registros en el UR3 coincide con lo configurado en el scan list de Horner
  • Verificar que ningun firewall bloquea el puerto 502
  • El problema ya no es de red sino de protocolo/aplicacion

Aparece una ruta incorrecta en Windows

Si route print muestra que la red 192.168.1.0 sale por la interfaz 192.168.3.228, esa ruta esta mal. Eliminarla:

route delete 192.168.1.0

La red .1 esta conectada directamente a la PC por Ethernet y no necesita ruta indirecta.

14. Checklist Operativo

Seguir este checklist en orden para poner en marcha la comunicacion UR3 ↔ PLC:
  1. 1UR3 con IP 192.168.1.76, mascara 255.255.255.0, gateway 192.168.1.28
  2. 2PC Windows: Ethernet con 192.168.1.28 (sin gateway)
  3. 3PC Windows: Wi-Fi con 192.168.3.228 (gateway 192.168.3.1)
  4. 4ping 192.168.1.76 desde Windows responde OK
  5. 5Forwarding habilitado en ambas interfaces (Set-NetIPInterface)
  6. 6IPEnableRouter = 1 en registro de Windows
  7. 7route print muestra ambas redes como On-link
  8. 8PLC con IP 192.168.3.12, gateway 192.168.3.228
  9. 9En Cscape: Modbus Client habilitado, dispositivo UR3 en 192.168.1.76:502
  10. 10Scan list configurado con los registros deseados
